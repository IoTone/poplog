\chapter{Pop-11 fundamentals}

Pop-11 reads like an Algol-descended imperative language and behaves like a
Lisp with a stack machine underneath. It has infix syntax, block keywords
that always close (\code{endif}, \code{endfor}, \code{enddefine}), dynamic
typing, garbage collection, first-class procedures, and an extensible
reader. What makes it distinctive is the \emph{open stack}, and almost
everything idiomatic follows from it.

\section{Syntax at a glance}

\begin{pop}
;;; comments run from three semicolons to end of line
vars x = 5;              ;;; a global (permanent) variable
x + 1 -> x;              ;;; ASSIGNMENT POINTS RIGHT: value -> destination
npr('x is ' sys_>< x);   ;;; print a line; sys_>< concatenates anything
x =>                     ;;; the REPL's printer: "** 6"
\end{pop}

The assignment arrow is the first thing to internalise: \code{-> x} reads
``into \code{x}''. It points that way because assignment is a stack
operation --- the value is already there, and the arrow says where to put it.

\section{Words and strings}

\begin{pop}
'a string'      ;;; single quotes: a mutable vector of characters
"aword"         ;;; double quotes: a WORD -- an interned symbol, not a string
\end{pop}

This is the single most common beginner error, and it has a silent cousin.
Words are interned: two occurrences of \code{\dq apples\dq} are the same object.
Strings are not: two occurrences of \code{'apples'} are two objects that
merely print alike. Poplog's default hash table, \code{newproperty}, matches
keys by \emph{identity}, so string keys quietly miss:

\begin{pop}
vars tbl = newproperty([], 50, false, true);
3 -> tbl("apples");
tbl("apples") =>          ;;; ** 3        -- words are identity-equal
tbl("pears")  =>          ;;; ** <false>  -- the default

vars m = newmapping([], 50, false, true);   ;;; compares keys with =
7 -> m('a string key');
m('a string key') =>      ;;; ** 7
\end{pop}

Use words as keys, or use \code{newmapping}. Both are right; silently missing
is not.

\section{Lists, vectors, and the quoting trap}

\begin{pop}
[1 2 3]                   ;;; list:    hd(l), tl(l), length(l), l(2)
{1 2 3}                   ;;; vector:  constant-time subscript
\end{pop}

List brackets \emph{quote} their contents, like Lisp's \code{'(...)}. So
\code{[x (n + 1)]} is a list of the literal words \code{x ( n + 1 )}. To
evaluate, escape with \code{\textasciicircum} (one item) or
\code{\textasciicircum\textasciicircum} (splice a list):

\begin{pop}
vars n = 4, rest = [d e];
[^n ^(n + 1) c ^^rest] =>     ;;; ** [4 5 c d e]
\end{pop}

\section{Procedures}

A procedure's result is whatever it leaves behind; there is no \code{return}
statement, and the last expression is the value.

\begin{pop}
define double(n);
    n * 2
enddefine;
double(21) =>                 ;;; ** 42
\end{pop}

A procedure may leave \emph{several} results, which the caller collects in
reverse order:

\begin{pop}
define divmod(a, b);
    a div b, a mod b
enddefine;
vars q, r;
divmod(17, 5) -> r -> q;
npr('17 = ' sys_>< q sys_>< '*5 + ' sys_>< r);   ;;; 17 = 3*5 + 2
\end{pop}

Closures are made by partial application with \code{\%\ldots\%}:

\begin{pop}
define mult(a, b); a * b enddefine;
vars triple = mult(% 3 %);
triple(14) =>                 ;;; ** 42
\end{pop}

And every accessor has an \emph{updater} --- the procedure that runs when it
appears on the left of an arrow. This is why \code{l(2)} both reads and
writes, and why you can give your own procedures assignable behaviour:

\begin{pop}
vars l = [a b c d];
l(2) =>                       ;;; ** b
"BEE" -> l(2);
l =>                          ;;; ** [a BEE c d]
\end{pop}

\section{The open stack}

There is one user-visible stack, and it is not hidden by the calling
convention. A procedure can leave zero, one, or a hundred results, and the
number need not be known until it runs.

\begin{pop}
define upto(n);
    lvars i;
    for i from 1 to n do i endfor    ;;; leaves n results on the stack
enddefine;

[% upto(5) %] =>              ;;; ** [1 2 3 4 5]
{% upto(5) %} =>              ;;; ** {1 2 3 4 5}
\end{pop}

\code{[\%\ \ldots\ \%]} means ``run this, and make a list of everything it
left''. That one construct replaces most of what other languages need
generators, varargs, spread operators and comprehensions for. It also makes
Forth nearly free to host (Chapter~6): Forth's data stack \emph{is} this
stack.

\begin{callout}{Why this matters for performance}
Because results are passed on the stack rather than boxed into tuples,
multiple return values cost nothing, and neither does a procedure that
sometimes returns nothing. The \code{nfib} and \code{closures1M} benchmark
rows in Chapter~1 are measuring this calling convention.
\end{callout}

\section{Control structures}

Every opener has a matching closer.

\begin{pop}
if x > 3 then npr('big') elseif x = 3 then npr('exact') else npr('small') endif;
unless ready then wait() endunless;

for i from 1 to 10 do ... endfor;
for item in list do ... endfor;
while cond do ... endwhile;
repeat ... quitif(done); ... endrepeat;

define classify(n);
    switchon n
        case < 0 then 'negative'
        case = 0 then 'zero'
        else 'positive'
    endswitchon
enddefine;
classify(-5) =>               ;;; ** negative
\end{pop}

\section{Scope, and \code{dlocal}}

\code{vars} declares a permanent (global) identifier; \code{lvars} declares a
lexical local inside a procedure --- prefer \code{lvars}. \code{constant} and
\code{lconstant} are their immutable counterparts.

\code{dlocal} is the one with no close equivalent elsewhere: it gives a
variable a new value for the \emph{dynamic extent} of a procedure call, and
restores the old value on exit --- whether the procedure returns normally,
jumps out, or is unwound by a mishap.

\begin{pop}
vars indent = '';
define show(x);
    dlocal indent = indent >< '  ';
    npr(indent sys_>< x);
    if x > 1 then show(x - 1) endif;
enddefine;
show(3);
\end{pop}
\begin{repl}
  3
    2
      1
\end{repl}

After \code{show} returns, \code{indent} is empty again. The same mechanism
is how Poplog rebinds output streams, the current character repeater, and the
compiler's own state safely --- it is Pop-11's answer to
\code{try\ldots finally}, and it is declarative.

\section{The list matcher}

Pop-11's pattern matcher works on lists and is built into the language with
the \code{matches} operator. \code{?x} binds one item, \code{??x} binds a
(possibly empty) segment, \code{=} matches one item without binding.

\begin{pop}
vars db = [[tom likes cats] [ann likes dogs] [tom likes jazz]];
vars item, what;              ;;; pattern variables must be permanent (vars)
for item in db do
    if item matches [tom likes ?what] then
        npr('tom likes ' sys_>< what)
    endif
endfor;
\end{pop}
\begin{repl}
tom likes cats
tom likes jazz
\end{repl}

\begin{callout}{A trap worth naming}
The matcher assigns through the \emph{permanent} identifier, so pattern
variables declared with \code{lvars} are silently not filled in --- you get
\code{<undef>}. Declare them \code{vars}.
\end{callout}

This matcher, plus a dozen lines of ranking and reassembly, is the whole of
ELIZA; \code{examples/eliza.p} in the tree is a faithful implementation of
Weizenbaum's original, script file and all.

\section{Objects: Objectclass}

Objectclass is Pop-11's CLOS-like object system: classes with slots, and
generic procedures with methods dispatched on argument class.

\begin{pop}
uses objectclass;

define :class Account;
    slot acct_name = 'anon';
    slot acct_balance = 0;
enddefine;

define :method deposit(a:Account, n);
    acct_balance(a) + n -> acct_balance(a);
    a
enddefine;

define :method print_instance(a:Account);
    printf('<Account %p: %p>\n', [% acct_name(a), acct_balance(a) %]);
enddefine;

vars acc = newAccount();
'ada' -> acct_name(acc);
deposit(acc, 100);
deposit(acc, 42);
print_instance(acc);          ;;; <Account ada: 142>
\end{pop}

Slots come with accessors \emph{and} updaters for free, which is why
\code{acct\_balance(a)} works on both sides of the arrow.
